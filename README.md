# cyclewr-survey-2026.github.io
Results of the municipal candidate survey 2026 conducted by CycleWR.

A static site (plain HTML/CSS/JS, no build step) served by GitHub Pages.

> **Status: design prototype.** Survey questions, candidates and ward shapes in `data/` are
> **placeholders** generated by `scripts/make_demo_data.py`. Replace them before launch.

## Pages

| Page | URL | What it shows |
|---|---|---|
| Home | `/` | Clickable ward map + directory of every race (the accessible alternative to the map) with "responded / total" counts |
| Race | `/race.html?id=kitchener-ward-3` | One race. **Browse by topic** (5 topic tabs, every candidate's answer under each question, yes/no tally) or **by candidate** (all of one candidate's answers across all topics). "Also on your ballot" links to mayor / regional races. |
| Deep links | `…#topic=safety`, `…#candidate=candidate-14` | Every topic and every candidate view is shareable |
| About | `/about.html` | Methodology and the full question list |

Candidates are listed alphabetically by surname. Non-responders are shown as "Did not respond".

## Data files (`data/`)

- `survey.json` — the 5 topics and their questions. `type` is `"choice"` (with `choices`, e.g. Yes/No/Unsure — shown as coloured chips) or `"open"` (free text).
- `races.json` — municipalities and races (`Regional Chair`, `Mayor`, `Regional Councillor`, `Ward Councillor`).
- `candidates.json` — one entry per candidate: `race`, `responded`, and `answers` keyed by question id: `{ "choice": "Yes", "comment": "…" }`.
- `wards.geojson` — ward polygons; each feature needs `properties.race` matching a race id in `races.json`.

Ward boundaries: download the official ward boundary layers from the Region of Waterloo /
City of Kitchener / City of Waterloo / City of Cambridge open data portals, export as GeoJSON
(WGS84), simplify (e.g. mapshaper.org) and add the `race` property.

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```
